# SMP Card Assistant — контекст проекта

## Цель
Создать Windows-программу и расширение Chrome для подготовки шаблонов карты вызова СМП и переноса выбранных данных в электронную карту на сайте Promed.

## Репозиторий
https://github.com/adamant1990/SMP-Card-assistant

## Подтверждённые решения
- Платформа: Windows-программа + расширение Chrome.
- Windows-приложение: планируется Electron + React + TypeScript.
- Расширение: Chrome Manifest V3.
- Хранение: локальные JSON-файлы, без обязательного сервера.
- Поддержать оба типа шаблонов: отдельные текстовые заготовки и шаблон целой карты.
- Автоматическое сохранение карты запрещено: пользователь проверяет данные и сохраняет вручную.
- Не изменять другие проекты пользователя.
- Работать небольшими этапами, не повторять уже предоставленные материалы без необходимости.

## Сайт
Пользователь указал адрес: https://smpufav2.giszrb.ru

## Источник для интеграции
Пользователь ранее прислал неполный JSON-сценарий Automa «карта вызова 1». В нём используются Ext JS, действия заполнения форм и клики, поля жалоб, анамнеза, эпиданамнеза, осмотра, жизненных показателей, диагноза, помощи и рекомендаций. Встречаются хрупкие CSS-селекторы с nth-child(...).

Сценарий Automa неполный: часть начальных узлов и связей отсутствует. Не считать все селекторы проверенными. Перед применением проверить реальные поля на тестовой карте через DevTools и по возможности заменить хрупкие селекторы на устойчивые признаки.

## Текущий проверенный прототип расширения — v0.1.0
Путь: `extension/`

- Создано расширение Chrome Manifest V3 для сайта `smpufav2.giszrb.ru`.
- Причина обращения выбирается из справочника Ext JS по значению `cmpreasonnew_name`, а не по временному ID DOM-модели.
- Поля жалоб и анамнеза заполняются по `textarea[name="complaints"]` и `textarea[name="anamnez"]`.
- Пользователь подтвердил, что заполнение причины обращения, жалоб и анамнеза работает стабильно.
- Расширение не сохраняет карту автоматически и не отправляет данные на внешние серверы.
- Диагноз `input[name="diag_id"]) пока только обнаруживается; штатный выбор диагноза из справочника ещё не проверен и не реализован.
- Перед ручным сохранением пользователь должен визуально проверить все заполненные поля.

## Безопасность и медицинские данные
- Не хранить в репозитории реальные данные пациентов, токены, пароли или данные авторизации.
- Не использовать медицинские значения из демонстрационного сценария как универсальные значения по умолчанию.
- Индивидуальные диагнозы, показатели, назначения и результаты должны вводиться/подтверждаться пользователем.
- Расширение не должно нажимать «Сохранить».
- Не отправлять содержимое карт на внешние серверы.

## План этапов
1. Базовая структура проекта и документация.
2. Утвердить схему JSON и проверку шаблонов.
3. Реализовать Windows-редактор шаблонов и локальные импорт/экспорт.
4. Расширить проверенное расширение Chrome: загрузка JSON, выбор разделов, заполнение.
5. Реализовать и проверить штатный выбор диагноза из справочника ProMed на тестовой карте.
6. Проверить дополнительные поля и устойчивость к перерисовке Ext JS.
7. Проверить сценарии ошибок, убедиться, что сохранение не выполняется автоматически.
8. Подготовить сборки Windows и инструкцию установки.

## Связь Windows-шаблонов с расширением (2026-10-17)
- Windows-программа сохраняет шаблоны локально автоматически и экспортирует их в JSON.
- Расширение Chrome поддерживает импорт этого JSON в локальное хранилище Chrome.
- В popup можно выбрать импортированный диагноз и перенести поля «Жалобы» и «Анамнез» в форму расширения; флажки заполнения включаются только для непустых текстов.
- Перед переносом показывается подтверждение, если поля жалоб/анамнеза уже заполнены.
- На этом этапе поля «Объективный осмотр» и «Лечение и рекомендации» импортируются в локальный список, но намеренно не подставляются в ProMed: требуется точное сопоставление с проверенными полями.
- Расширение не нажимает сохранение карты и не отправляет данные на внешние серверы.
- Добавлен отдельный workflow для проверки синтаксиса и упаковки расширения Chrome в ZIP.
